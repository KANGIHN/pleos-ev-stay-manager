# 정차 대기 배터리 매니저

귀가 경로에 필요한 에너지를 남기는 공조 체류 계획 앱입니다. 첫 화면은 **몇 시까지 머물 수 있나 / 예정 시각까지 부족한가 /
어떤 설정이면 충족하나**를 먼저 보여 주고(모두 현재 가정에 근거한 추정), **귀가 예비선** 밑으로 내려가기 전에 알립니다.

## 화면

P단(정차)용 앱입니다. Pleos 에뮬레이터에서는 D단이 되면 시스템이 앱 화면을 가립니다.
앱 자체도 주행 중(D·R·N 또는 `CarUxRestrictionsManager`가 주의 분산 최적화를 요구할 때)에는 한 줄 안내만
남기도록 되어 있지만, Pleos에서는 시스템 차단 때문에 이 한 줄은 보이지 않습니다.

- **판단 카드(첫 화면 왼쪽 위)**: ① 몇 시까지 머물 수 있나 — 귀가 예비선까지 지금 설정을 유지할 때의 시각 범위
  ("HH:mm ~ HH:mm까지", 아래에 "약 3.4 ~ 5.7시간"). ② 예정 시각까지 부족한가. ③ 어떤 설정이면 충족하나 — 비교한 설정 중
  범위의 짧은 쪽 기준으로 부족분을 메우는 것(공조를 유지하는 대안 우선). 없으면 가장 효과가 큰 대안과 함께 숫자로
  "HH:mm에 예비선 도달 — 약 N분 일찍 출발", "약 X%(약 Y kWh) 충전 필요"(지금 설정 기준, 충전하는 동안의 소모 제외,
  100%로도 부족하면 그렇게 표시)를 보여 줍니다.
  귀가 상태는 셋으로 나눕니다 — 계산 가능 / 정보 부족("귀가 보장 계산 불가 — 여유분 기준", 이때 예정 시각 "충족 예상"은
  "귀가 판단 보류 — 집까지 정보 없음"으로 보류하고 부족 판정은 그대로) /
  "현재 가정상 귀가 잔량 부족"(시간을 내지 않음). 공조 값을 일부 읽지 못하면 `부분 추정` 배지를 붙입니다.
  바깥 기온 입력이 10°C 미만이고 귀가 소모가 거리 기반이면 "저온 주행 보정 없음 — 귀가 소모가 더 클 수 있음"을 표시합니다.
- **상세 보기(오른쪽 아래 버튼)**: 소모율과 출처, 차량 신호(원시값·단위 확인 여부), 계산 가정 목록. 기본은 접혀 있습니다.
- **머물 예정 시각**: 날짜·시각으로 저장합니다(30분 단위). "현재 가정상 충족 예상 · 여유 N분" 또는
  "현재 가정상 N분 부족"을 표시하고(범위의 짧은 쪽 기준), 그 시각이 지나면 "대기 완료"로 바꿉니다.
  충족 여부와 "어떤 설정이면 충족하나"는 반올림 전 값으로 판정합니다(1분 미만 부족도 "1분 부족").
- **알림 범위**: 정차 감시 서비스가 실행 중(서비스가 시작을 알려 옴)이고 기어 P가 확인될 때만 보냅니다.
  예비선·예정 시각 부족 경고는 앱이 화면에 없을 때, "대기 완료"는 예정 시각 도달 시 한 번 보냅니다.
  P를 벗어나거나 감시를 끝내면 세션을 먼저 끝내고 이미 올라간 경고·대기 완료 알림을 지웁니다.
  감시가 꺼져 있거나 기어를 확인하지 못하면 알림 없이 화면 안 경고만 있습니다(`domain/NotificationGate.kt`).
  "앱이 화면에 없을 때"는 다른 앱이 이 앱 위에 열린 경우입니다. Pleos에서는 홈 키를 눌러도 이 앱이 자기 화면 영역에 계속 떠 있어(화면에 보이는 상태 유지) 경고 알림을 보내지 않고 화면 안 경고만 보입니다.
  에뮬레이터 v2.1.0에서 r5 APK로 확인한 것: 감시 시작 → "정차 감시 중"과 상시 알림, 다른 앱을 위에 띄운 상태에서 SoC 7→6%일 때
  「귀가 예비선 경고」 알림 "현재 가정상 귀가 예비선(10%) 아래입니다. 출발하거나 충전을 검토하세요." 표시, 기어를 D로 바꾸면 앱 알림이 모두 지워지고 서비스가 멈춤.
  r6 APK로 확인한 것: P단에서 강제 종료 뒤 다시 열면 감시가 스스로 다시 시작되어 "정차 감시 중"과 서비스 실행.
  2026-11-13 최신 APK로 확인한 것: 체류 조건 창 표시·조작, 잔량 20% 예비선 아래 경고, D단 전환 시 화면 가림·감시 종료(시연 영상).
  확인하지 못한 것: 화면 꺼짐 중 동작, 예정 시각 부족·"대기 완료" 알림, 귀가 판단 보류 화면(단위 테스트만).
- **정차 감시(세션)**: '정차 감시 시작'을 누르면 foreground service(유형 `specialUse`)를 시작합니다. 화면은 먼저
  "정차 감시 시작 중…"을 보이고, 서비스가 `startForeground`에 성공했다고 알려 온 뒤에만 "정차 감시 중"으로 바뀝니다.
  시작 거부(예외), `startForeground` 실패, 10초 안에 응답 없음, 감시 중 서비스 종료는 "정차 감시를 시작하지 못함(이유)"와
  '다시 시도' 버튼으로 표시합니다. 알림 권한이 없으면 "알림 권한이 꺼져 있어 앱 밖에서는 경고를 보낼 수 없습니다"와
  '알림 권한 요청' 버튼을 보입니다. '감시 종료'를 누르거나 D·R·N으로 바뀌면 끝납니다.
- **체류 조건(감시 시작 시 한 번)**: '정차 감시 시작'을 누르면 한 화면에서 난방(공조) 유지 여부, 난방 유지면 대안의 최저 설정 온도,
  동승자 유무를 묻습니다. '건너뛰고 시작'하면 이전(기본) 조건으로 시작합니다 — 기본은 난방 끄기도 비교·동승자 없음이라 시연 시나리오 수치가 그대로입니다.
  난방 유지면 공조를 끄는 대안을, 동승자가 있으면 조수석 열선을 끄는 대안을 빼고("공조 끄고 앞좌석 열선 2단씩(조수석 유지)"로 대체),
  설정 온도를 최저 설정 온도 아래로 내리는 대안을 뺍니다. 감시 카드의 '조건 바꾸기'로 나중에 바꿀 수 있습니다.
  앱을 강제 종료한 뒤 다시 열면 저장된 세션을 그대로 "감시 중"으로 두지 않습니다: 기어 P가 확인되고 예정 시각이 지나지 않았으면
  서비스를 다시 시작하고(결과는 위와 같은 경로로 표시), 그렇지 않거나 10초 안에 기어를 읽지 못하면 세션을 끝내고 "정차 감시 꺼짐"으로 둡니다
  (`domain/SessionRestore.kt`).
  서비스가 도는 동안 프로세스가 살아 있어 2초 주기 계산이 이어지도록 한 설계입니다. 화면 꺼짐·프로세스 회수 시 동작과
  시작 실패 표시 경로는 에뮬레이터에서 확인하지 못했습니다(순수 로직 단위 테스트만 있음).
- **귀가 예비선 막대**: 현재 잔량, 집까지 필요한 잔량, 사용자 여유분, 예비선 위치를 한 막대에 표시합니다.
  예비선에 가까워지면(남은 잔량 3%p 미만 또는 30분 미만) 경고, 예비선 아래면 "지금 출발하거나 충전" 경고를 띄웁니다.
  정차 감시 중이고 다른 앱이 위에 있을 때는 같은 경고를 Android 알림(채널 「귀가 예비선 경고」)으로 보냅니다(위 알림 범위·확인 내역).
- **설정을 바꾸면**: "온도 2도 낮추면 약 +20분 (추정, 중앙 소모율 기준)", "풍량 6단→4단(2단계 줄임)"(실제 단 차이를 표시),
  "온도 2도 낮추고 풍량 6단→4단", "공조 끄고 운전석 열선 2단만(조수석 끔) 쓰면"을 비교합니다.
  설정 카드의 **대안의 최저 설정 온도**(기본 안 씀, 처음 누르면 20°C, 10~28°C)를 정하면 공조 설정 온도를 그보다 낮추는 대안과
  공조를 끄는 대안은 빼고 비교·제안합니다. 실제 실내 온도는 읽지도 계산하지도 않으므로, 이 값은 실내 온도 보장이 아니라 대안의 설정 온도 하한입니다.
  앱은 차량 설정을 바꾸지 않습니다(조회 권한만 사용).
- **차량 신호**: 각 값 옆에 `실측`(차량 신호), `추정`(앱 계산), `내비 예상`, `사용자 설정`, `지원 안 됨`을 표시합니다.
- **계산 가정**: 바깥 기온(사용자 입력), 읽지 못해 대체한 값(용량·전비·공조), 범위 폭("가정 범위(미검증)"),
  측정 구간 상태와 실측 전환에 걸리는 시간, 제외한 집 정보를 표시합니다. 공조 소비 모델 계수는 화면에 없고
  `domain/StayModels.kt`의 `Assumptions`에 있습니다. 착석 신호는 표시만 하고 계산에는 쓰지 않습니다.
- **시연 모드**: 켜면 앱 시계가 60배로 흐르고 상단에 `시연 모드 · 시간 ×60` 배지가 붙습니다.

## 계산 방식

판단 로직은 SDK와 분리된 순수 Kotlin(`app/src/main/java/kr/appdevchallenge/evstay/domain/`)이며 JUnit 테스트 89개가 있습니다.

1. **측정 구간**: P단이 확인될 때만 잔량을 기록합니다(기어를 읽지 못하면 기록하지 않고 설정 기반 추정만 씁니다). 공조 전원·온도·풍량·에어컨·열선이 바뀌거나 P단을 벗어나면
   기록을 비우고 새 구간을 시작합니다. 값을 잠깐 읽지 못한 경우(null)는 변경으로 보지 않습니다.
2. **소모율**: 잔량(SoC)은 1% 단위라서, 구간 안의 연속 하락 지점 사이 시간으로 %/시간을 계산합니다.
   하락이 3번 미만이면 공조 설정 기반 모델(기본 부하 + 설정 온도와 바깥 기온 차 + 풍량 + 에어컨 + 열선)을 씁니다.
   바깥 기온은 사용자가 입력합니다(기본 0°C). 하락 폭이 4%p에 이를 때까지는 두 값을 섞고, 범위 폭은 ±25%에서 ±10%로
   줄어듭니다. 이 폭은 검증된 오차가 아니라 정한 값입니다("가정 범위(미검증)").
   소모가 적으면 실측 전환이 늦습니다(공조를 끈 모델 추정이면 약 11.6시간). 기록 창은 12시간입니다.
   공조 전원·에어컨을 읽지 못하면 꺼짐으로 가정하지 않고, 꺼짐~켜짐 양쪽으로 계산해 범위를 넓힙니다.
   잔량이 5%p 이상 한 번에 바뀌면(콘솔 입력·충전) 기록을 새로 시작하고, 잔량이 오르면 충전 중으로 보고 계산하지 않습니다.
3. **귀가 예비선** = 집까지 필요한 잔량 + 사용자 여유분(기본 10%).
   집까지 필요한 잔량은 다음 순서로 구합니다: 내비 `requestTrip`의 도착 시 예상 잔량 → 내비 경로 거리 →
   직접 입력한 거리 → 내비 현재 위치와 집 좌표의 직선거리 × 1.3. 거리는 전비로 환산하고 10% 여유를 더합니다.
   내비 경로 예상이 실패했거나 집(목적지)이 바뀌면 이전 경로 값을 쓰지 않습니다.
   `onTripInfo`에는 요청 식별자가 없으므로 요청마다 순번을 매기고 한 번에 하나만 보냅니다(`domain/TripRequestTracker.kt`).
   응답의 `TripSummary.routePoints`에 목적지 좌표가 있으면 요청한 집과 1km 안일 때만 쓰고, 이전 요청의 목적지면 버립니다.
   목적지 좌표가 없으면 순서로 판단합니다 — 응답 전에 집이 바뀌면 그 응답은 버리고, 30초 안에 답이 없으면 그 요청을 보낸 뒤
   10분까지 새 요청을 보내지 않고 그 사이 오는 응답을 버립니다.
   **남은 위험**: 목적지 좌표 없는 응답이 10분보다 늦게 오고 그때 새 요청이 나가 있으면 새 요청의 응답으로 받아들입니다
   (테스트 `residualRisk_…`가 이 동작을 고정해 둡니다). 그때는 직선거리 대조만 남고, 거리가 비슷한 다른 목적지는 못 거릅니다.
   내비가 `routePoints`에 목적지를 채우는지는 에뮬레이터에서 확인하지 못했습니다.
   받은 경로 거리는 집까지 직선거리의 0.9~4배일 때만 씁니다.
   **신뢰 구분**: 직접 입력 거리, 목적지가 일치한 내비 응답(응답 귀속 확인), 직선거리와 대조한 내비 응답(거리 개연성만 확인 — 비슷한 거리의
   다른 목적지 응답은 구분 못 함)은 판단에 씁니다. 목적지도 없고 직선거리 대조도
   못 한 내비 응답(현재 위치·집 좌표 없음 또는 직선거리 0.5km 미만)은 미확인입니다 — 직접 입력 거리보다 뒤 순위이고, 그것밖에 없으면
   "충족 예상" 대신 "귀가 판단 보류 — 내비 응답 미확인"과 직접 입력 안내를 보입니다(경고 방향 판정은 그대로). 내비 응답은 15분이 지나면
   만료되어 쓰지 않습니다(`domain/HomeCandidates.kt`). 상세 영역에 내비 경로 거리 원시값과 "단위 미확인(미터로 해석)"을 표시합니다.
   거리 기반 귀가 소모에는 저온 주행 전비 보정을 하지 않습니다(크기를 정할 근거 자료 없음). 그래서 판정 문구는 모두
   "현재 가정상"이고, 바깥 기온 입력이 10°C 미만이면 첫 화면과 계산 가정에 "귀가 소모가 더 클 수 있음"을 표시합니다.
   앞좌석 열선은 운전석·조수석을 따로 보며, 어느 쪽이든 값이 없는 좌석(지원 안 됨, 처음 읽는 중, 지원되지만 값 없음)은 꺼짐~3단 사이로 계산합니다.
   명백히 잘못된 값만 '신뢰할 수 없음'으로 제외하고 다음 후보를 씁니다 — 1,500km를 넘는 거리, (0,0)·범위 밖 좌표,
   내비 응답 자체의 음수 도착 잔량. 요청 뒤 잔량이 줄어 현재 잔량 기준으로 다시 맞춘 도착 잔량이 음수가 되는 것은 버리지 않고
   귀가 잔량 부족으로 판정합니다(귀가 소모 = 요청 당시 잔량 − 도착 예상 잔량). 정상적인 장거리 경로는 제외하지 않고, 필요 잔량이 현재 잔량(또는 100%)보다 크면 "현재 가정상 귀가 잔량 부족"으로 판정합니다.
   잔여 주행거리 0 이하는 실측값이 아니라 '모름'으로 처리합니다.
4. **집 찾기**: 내비 즐겨찾기 중 `HOME`을 씁니다. 없으면 최근 목적지 3곳 중에서 고를 수 있습니다.

## SDK 값의 단위 근거

| 값 | 확인한 근거 | 앱의 처리 |
|---|---|---|
| `getEvBatteryCapacity` | **확인함(Pleos Connect Emulator v2.1.0)**: Virtual Console 77.4kWh가 SDK 원시값 77400.0으로 옴 → Wh. 다른 차종은 미확인 | ÷1000으로 kWh. 5~250kWh 밖이면 '모름'(기본 77.4kWh 가정으로 표시). 상세에 원시값과 "단위 확인: 에뮬레이터 v2.1.0" 표시 |
| `getRangeRemainingDistance` | **미확인**. 반환형 `Float`, 변환 없음. 에뮬레이터에서 0이 보고됨 | 0 이하는 '모름'. 2000 초과면 m로 보고 ÷1000. 상세에 원시값과 "단위 미확인" 표시 |
| `getCurrentEvEfficiency` | **미확인**. 반환형 `Float`, 단위 설명 없음 | 1~15는 km/kWh, 50~400은 Wh/km로 보고 환산, 그 밖은 '모름'. 상세에 원시값과 "단위 미확인", 계산 가정에 "차량 전비 값은 단위 미확인" 표시 |
| `getEvBatteryStateOfCharge` | 반환형 `Integer`, 에뮬레이터에서 Virtual Console 값(35)과 같은 값 확인 | % 그대로 |
| `TripInfo.distance` | **미확인**. 반환형 `Int`, 단위 설명 없음 | 미터로 해석하되 직선거리와 맞지 않으면 버림. 대조하지 못하면 '미확인' 입력으로 보고 귀가 판단 보류. 상세에 원시값과 "단위 미확인(미터로 해석)" 표시 |
| `getHvacTemperature` | `TemperatureUnit.CELSIUS`를 인자로 지정 | °C |

추정 규칙이 남은 항목(잔여 주행거리·전비·경로 거리)은 원시값과 "단위 미확인"을 화면에 같이 보여 주어 실제 단위를 확인할 수 있게 했습니다.

### Virtual Console 시연 순서

`adb forward tcp:8088 tcp:8088` 후 `http://127.0.0.1:8088`을 엽니다.

1. 기어 P, 배터리 용량 77.4kWh, SoC 35%, 공조 켜짐·26°C·풍량 6으로 설정하고 앱을 엽니다.
2. 앱 오른쪽 '설정'에서 **집까지 거리 직접 입력**을 40km로 맞춥니다(내비 즐겨찾기 '집'이 있으면 내비 값이 먼저 쓰입니다).
3. 판단 카드에 "(지금 + 3.4시간) ~ (지금 + 5.7시간)까지", "약 3.4 ~ 5.7시간 · 귀가 예비선 21%까지", 저온 보정 없음 안내가,
   '설정을 바꾸면'에 "온도 2도 낮추면 약 +20분 (추정, 중앙 소모율 기준)"이 표시됩니다
   (전비를 읽지 못해 5km/kWh로 계산될 때의 값으로, 단위 테스트로 확인한 계산값입니다. 차량이 전비나 잔여 주행거리를 주면 달라집니다).
4. **시연 모드**를 켜고 SoC를 20초(앱 시계로 20분) 간격으로 34 → 33 → 32 → 31 → 30%로 내리면
   32%부터 소모율이 '잔량 변화 + 공조 설정 혼합'(약 3%/시간 실측과 설정 추정을 섞음), 30%에서 '최근 잔량 변화 기반'으로 바뀝니다.
5. 시연 모드를 끄고 SoC를 35%로 되돌린 뒤 '정차 감시 시작'을 누르고 체류 조건 창에서 '건너뛰고 시작'을 고르면 "정차 감시 시작 중…" 뒤 서비스가 시작되면 "정차 감시 중"과 상시 알림 「정차 감시 중」이 뜹니다.
   '머물 예정 시각'을 + 로 켜고(처음 누르면 약 2시간 뒤) 4시간 뒤로 맞추면 "… 약 34분 부족"이 표시되고, ③에 "공조 끄고 운전석 열선
   2단만(조수석 끔) 쓰면 → 충족 예상"이 나옵니다(35% 상태 기준, 단위 테스트로 확인한 계산값).
   공조 온도를 바꾸면 측정 구간이 새로 시작되어 바뀐 설정 기준으로 다시 계산됩니다.
   시연 모드에서는 목표 시각까지 남은 시간도 60배로 줄어드므로, 이 단계는 시연 모드를 끈 상태에서 보는 것이 읽기 쉽습니다.
6. SoC를 22%로 바꾸면 "현재 가정상 곧 귀가 예비선에 닿습니다" 경고, 20%로 바꾸면 "현재 가정상 귀가 예비선 아래" 경고가 뜹니다.
   직접 입력 거리를 200km로 올리면 "현재 가정상 귀가 잔량 부족"이 표시됩니다.
7. 기어를 D로 바꾸면 Pleos 시스템이 앱 화면을 가리고 정차 감시도 끝납니다. P로 돌리면 앱 화면이 돌아오고 새 측정 구간이 시작됩니다.
